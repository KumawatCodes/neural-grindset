## SECTION 1 — HBase Architecture & Theory (Viva)

### What is HBase?

- NoSQL, column-family distributed database built on top of HDFS
- Modeled after Google Bigtable paper
- Provides random, real-time read/write access on large datasets
- HDFS alone is sequential read/write — HBase adds random access on top
- Strong consistency model
- Not for complex SQL joins — use Hive for that

### Companies Using HBase (Viva Question)

- **Facebook** — messages inbox (billions of messages)
- **Twitter** — timeline storage
- **Adobe** — social analytics
- **Flipkart** — product catalog
- **Yahoo** — analytics platform

### HBase Data Model — Main Components (Viva Question)

```
Table
  └── Row  (identified by unique Row Key)
        └── Column Family (defined at table creation, groups columns)
              └── Column Qualifier (actual column name, added anytime)
                    └── Cell (value + timestamp)
```

**Row Key:**

- Unique identifier for each row
- Rows are stored sorted in lexicographic (alphabetical) order by row key
- Row key design is critical — determines data locality and query performance

**Column Family:**

- Groups related columns together
- Defined at table creation time (schema-level)
- Stored together on disk (same HFile)
- Example: `personal_info`, `academic_info`, `contact`

**Column Qualifier:**

- Actual column name within a column family
- Written as: `family:qualifier` → `personal_info:name`, `personal_info:age`
- Can be added anytime without altering schema — schema-free for qualifiers

**Cell:**

- Intersection of row + column family + column qualifier
- Contains: value (byte array) + timestamp (version identifier)
- Multiple versions of same cell stored by timestamp
- Default max versions kept = 3

**Timestamp:**

- Auto-assigned on write (current time in milliseconds)
- Used for versioning — latest timestamp = latest version returned on read
- Can be set manually

### What is Sparse Data? (Viva Question)

- In HBase, a row does not need to have values for every column
- If a cell has no value → it simply does not exist (no NULL stored, no storage wasted)
- This is called sparse data
- Contrast with RDBMS: NULL stored explicitly for every missing column
- HBase is ideal for data that is naturally sparse (user profiles, sensor data)

### What is a Column Family? (Viva Question)

- Logical and physical grouping of column qualifiers
- Defined at table creation — cannot add new column family without altering table
- All data in same column family stored in same HFile on HDFS
- Best practice: keep 1-3 column families per table
- Too many column families = too many HFiles open = performance hit
- Column qualifiers within a family are flexible — add anytime, no schema change needed

## SECTION 2 — HBase Shell Commands

### Namespace Commands

**What is Namespace?**

- Logical grouping of tables (like a database in RDBMS)
- Default namespaces: `default` (user tables), `hbase` (system tables)

```bash
# List all namespaces
hbase> list_namespace

# Create a namespace
hbase> create_namespace 'university'

# Describe a namespace
hbase> describe_namespace 'university'

# Drop a namespace (must be empty)
hbase> drop_namespace 'university'

# Create table inside a namespace
hbase> create 'university:students', 'personal', 'academic'

# List tables in a namespace
hbase> list_namespace_tables 'university'
```

### TTL for Columns (Viva Question)

**What is TTL?**

- Time To Live — set at column family level
- After TTL seconds, cells in that column family automatically expire
- Expired cells are removed during next Major Compaction
- Useful for: logs, session data, cache tables, sensor readings

**Can TTL Help Save Storage? (Viva Answer: YES)**

- Yes — expired data automatically deleted during compaction
- No manual DELETE needed
- Storage freed after major compaction runs
- Reduces maintenance overhead for time-limited data

```bash
# Create table with TTL of 1 hour (3600 seconds)
hbase> create 'session_data', {NAME => 'info', TTL => 3600}

# Add TTL to existing table
hbase> disable 'session_data'
hbase> alter 'session_data', NAME => 'info', TTL => 7200
hbase> enable 'session_data'

# Verify TTL
hbase> describe 'session_data'
# Look for: TTL => '3600 SECONDS (1 HOUR)'
```

## SECTION 3 — Filtering in HBase (Viva Only)

Filters applied on server side during SCAN — reduces data transferred to client.

### PrefixFilter — (Most Asked in Viva)

**What it is:**

- Filters rows where row key STARTS WITH a given prefix
- Only rows whose row key begins with the prefix are returned
- All other rows skipped at server side

**How to implement in shell:**

```bash
# Return only rows whose row key starts with 'S00'
hbase> scan 'students', {FILTER => "PrefixFilter('S00')"}

# Practical example: row keys like user_001, user_002, admin_001
# Get only user rows
hbase> scan 'logs', {FILTER => "PrefixFilter('user_')"}
```

---

### SingleColumnValueFilter — (Most Asked in Viva)

**What it is:**

- Filters rows based on value of a specific column
- Only rows where column value matches condition are returned

**How to implement in shell:**

```bash
# Get rows where personal_info:name = 'Himanshu'
hbase> scan 'students', {
  FILTER => "SingleColumnValueFilter('personal_info', 'name', =, 'binary:Himanshu')"
}

# Get rows where academic_info:marks > 80 (using comparator)
hbase> scan 'students', {
  FILTER => "SingleColumnValueFilter('academic_info', 'marks', >=, 'binary:80')"
}
```

**Comparators used with SingleColumnValueFilter:**

- `binary:value` — exact byte comparison
- `binaryprefix:value` — prefix comparison
- `regexstring:pattern` — regex match
- `substring:value` — substring match

---

### Other Filters (Know Names for Viva)

- **RowFilter** — filter based on row key with a comparator
- **ColumnPrefixFilter** — filter columns whose qualifier starts with a prefix
- **PageFilter** — limit number of rows returned (like LIMIT)
- **FamilyFilter** — filter by column family name
- **ValueFilter** — filter by cell value across all columns
- **TimestampsFilter** — filter by specific timestamps

### All Operations in One File

**File: `src/main/java/HBaseOperations.java`**

```java
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.hbase.HBaseConfiguration;
import org.apache.hadoop.hbase.TableName;
import org.apache.hadoop.hbase.client.*;
import org.apache.hadoop.hbase.util.Bytes;

public class HBaseOperations {

    // ----- CONFIGURATION -----
    // Which class creates HBase configuration? -> Configuration (Viva Answer)
    // HBaseConfiguration.create() returns a Configuration object with HBase defaults

    static Configuration getConfig() {
        Configuration config = HBaseConfiguration.create();
        // Replace with your HBase master container IP or hostname
        config.set("hbase.zookeeper.quorum", "localhost");
        config.set("hbase.zookeeper.property.clientPort", "2181");
        return config;
    }

    // ----- CREATE TABLE -----
    static void createTable(Connection conn) throws Exception {
        Admin admin = conn.getAdmin();
        TableName tableName = TableName.valueOf("students");

        if (admin.tableExists(tableName)) {
            System.out.println("Table already exists");
            admin.close();
            return;
        }

        // Define column families
        TableDescriptorBuilder tableBuilder =
            TableDescriptorBuilder.newBuilder(tableName);

        ColumnFamilyDescriptor cf1 =
            ColumnFamilyDescriptorBuilder.of("personal_info");
        ColumnFamilyDescriptor cf2 =
            ColumnFamilyDescriptorBuilder.of("academic_info");

        tableBuilder.setColumnFamily(cf1);
        tableBuilder.setColumnFamily(cf2);

        admin.createTable(tableBuilder.build());
        System.out.println("Table 'students' created successfully");
        admin.close();
    }

    // ----- INSERT DATA (PUT) -----
    // Viva: Explain insertion process in Java API
    // 1. Get Connection -> 2. Get Table object -> 3. Create Put with row key
    // 4. Add columns to Put -> 5. table.put(put) -> 6. Close table

    static void insertData(Connection conn) throws Exception {
        Table table = conn.getTable(TableName.valueOf("students"));

        // Put for row S001
        Put put1 = new Put(Bytes.toBytes("S001"));
        put1.addColumn(
            Bytes.toBytes("personal_info"),   // column family
            Bytes.toBytes("name"),             // qualifier
            Bytes.toBytes("Himanshu")          // value
        );
        put1.addColumn(
            Bytes.toBytes("personal_info"),
            Bytes.toBytes("age"),
            Bytes.toBytes("21")
        );
        put1.addColumn(
            Bytes.toBytes("academic_info"),
            Bytes.toBytes("marks"),
            Bytes.toBytes("85")
        );
        put1.addColumn(
            Bytes.toBytes("academic_info"),
            Bytes.toBytes("branch"),
            Bytes.toBytes("CSE")
        );

        // Put for row S002
        Put put2 = new Put(Bytes.toBytes("S002"));
        put2.addColumn(
            Bytes.toBytes("personal_info"),
            Bytes.toBytes("name"),
            Bytes.toBytes("Ravi")
        );
        put2.addColumn(
            Bytes.toBytes("academic_info"),
            Bytes.toBytes("marks"),
            Bytes.toBytes("72")
        );

        table.put(put1);
        table.put(put2);
        System.out.println("Data inserted successfully");
        table.close();
    }

    // ----- READ DATA (GET) -----
    static void getData(Connection conn) throws Exception {
        Table table = conn.getTable(TableName.valueOf("students"));

        Get get = new Get(Bytes.toBytes("S001"));
        Result result = table.get(get);

        // Read specific cell value
        byte[] nameVal = result.getValue(
            Bytes.toBytes("personal_info"),
            Bytes.toBytes("name")
        );
        byte[] marksVal = result.getValue(
            Bytes.toBytes("academic_info"),
            Bytes.toBytes("marks")
        );

        System.out.println("Name: " + Bytes.toString(nameVal));
        System.out.println("Marks: " + Bytes.toString(marksVal));
        table.close();
    }

    // ----- DELETE TABLE -----
    static void deleteTable(Connection conn) throws Exception {
        Admin admin = conn.getAdmin();
        TableName tableName = TableName.valueOf("students");

        if (!admin.tableExists(tableName)) {
            System.out.println("Table does not exist");
            admin.close();
            return;
        }

        // Must disable before dropping
        admin.disableTable(tableName);
        admin.deleteTable(tableName);
        System.out.println("Table 'students' deleted");
        admin.close();
    }

    // ----- MAIN METHOD -----
    public static void main(String[] args) throws Exception {
        Configuration config = getConfig();
        Connection conn = ConnectionFactory.createConnection(config);

        createTable(conn);
        insertData(conn);
        getData(conn);
        // deleteTable(conn);   // uncomment to test delete

        conn.close();
        System.out.println("Done.");
    }
}
```

### Explanation of Key Java API Classes (Viva)

|Class|Purpose|
|---|---|
|`Configuration`|Holds HBase connection config (ZooKeeper address etc.) — **Which class creates HBase config? → Configuration**|
|`HBaseConfiguration`|Factory — `HBaseConfiguration.create()` returns configured `Configuration` object|
|`ConnectionFactory`|Creates `Connection` to HBase cluster|
|`Connection`|Represents connection to HBase cluster — reuse, do not create per operation|
|`Admin`|For DDL operations: create table, disable, enable, delete table|
|`Table`|For DML operations: put, get, delete, scan|
|`Put`|Represents one row insert/update operation|
|`Get`|Represents one row read operation|
|`Result`|Holds data returned from Get or Scan|
|`Scan`|Represents multi-row read operation|
|`TableName`|Wraps table name string into HBase TableName object|
|`Bytes`|Utility class — converts String/int/long to byte[] and back|

---

### Insertion Process in Java API (Viva Question — Explain Step by Step)

1. Create `Configuration` using `HBaseConfiguration.create()`
2. Set ZooKeeper quorum address in config
3. Create `Connection` using `ConnectionFactory.createConnection(config)`
4. Get `Table` object: `conn.getTable(TableName.valueOf("tablename"))`
5. Create `Put` object with row key: `new Put(Bytes.toBytes("rowkey"))`
6. Add columns to Put: `put.addColumn(family_bytes, qualifier_bytes, value_bytes)`
7. Execute: `table.put(put)`
8. Close table: `table.close()`
9. Close connection: `conn.close()`

**Important:** All values in HBase Java API are byte arrays. `Bytes.toBytes()` converts String/int to byte[]. `Bytes.toString()` converts byte[] back to String.

## SECTION 6 — Viva Questions and Answers

**Q1: What is HBase? How is it different from HDFS?**

- HBase is a NoSQL database built on top of HDFS
- HDFS provides sequential read/write for large files — no random access
- HBase adds real-time random read/write capability on top of HDFS storage
- HDFS is a file system; HBase is a database

**Q2: Which companies use HBase?**

- Facebook (messages), Twitter (timeline), Adobe, Flipkart, Yahoo

**Q3: What are the main components of HBase data model?**

- Table → Row (identified by Row Key) → Column Family → Column Qualifier → Cell (value + timestamp)

**Q4: What is a Column Family?**

- Logical + physical grouping of column qualifiers
- Defined at table creation time (schema change requires alter)
- All columns in same family stored together in one HFile on disk
- Qualifiers within family can be added anytime without schema change

**Q5: What is sparse data?**

- Rows do not need values for every column
- Non-existent cells take zero storage (unlike RDBMS NULL which stores a value)
- HBase is designed for naturally sparse datasets (user profiles, sensor data)

**Q6: What is WAL and what is its use?**

- WAL = Write Ahead Log (also called HLog)
- One WAL file per RegionServer stored on HDFS
- Every write is logged to WAL BEFORE writing to MemStore
- Purpose: crash recovery — if RegionServer dies before MemStore flush, WAL is replayed to recover data
- Without WAL: in-memory MemStore data lost on crash

**Q7: What is MemStore?**

- In-memory write buffer, one per Store (per column family per Region)
- All writes go to MemStore after WAL write
- Data in MemStore is sorted by row key
- When MemStore reaches threshold (default 128MB) → flushed to HFile on HDFS
- Acts as write buffer to convert random writes into sequential HDFS writes

**Q8: Which command deletes a cell in HBase?**

- `delete` command — removes a specific cell (row key + column family + qualifier)
- `deleteall` — removes entire row (all columns)

**Q9: Which class creates HBase configuration?**

- `Configuration` class — obtained via `HBaseConfiguration.create()`
- Returns a `Configuration` object pre-loaded with HBase defaults

**Q10: What is PrefixFilter and how do you implement it?**

- PrefixFilter returns only rows whose row key starts with a given prefix
- Filtering happens on the server side (RegionServer) — reduces network transfer
- Shell: `scan 'table', {FILTER => "PrefixFilter('prefix')"}`
- Java API: `new PrefixFilter(Bytes.toBytes("prefix"))` passed to `Scan.setFilter()`

**Q11: What is SingleColumnValueFilter?**

- Filters rows based on the value of a specific column qualifier
- Only rows where the specified column matches the condition are returned
- Shell: `scan 'table', {FILTER => "SingleColumnValueFilter('cf','col',=,'binary:value')"}`
- Use case: find all rows where status='active', or age > 25

**Q12: Can TTL help save storage?**

- Yes — TTL (Time To Live) set at column family level
- After TTL seconds, cells in that family are marked expired
- Expired cells are physically removed during Major Compaction
- Eliminates need for manual DELETE of time-limited data (logs, sessions, cache)
- Reduces storage automatically over time

**Q13: Explain the insertion process in Java API (step by step)**

1. `Configuration config = HBaseConfiguration.create()` — create config
2. Set ZooKeeper address in config
3. `Connection conn = ConnectionFactory.createConnection(config)` — connect
4. `Table table = conn.getTable(TableName.valueOf("students"))` — get table handle
5. `Put put = new Put(Bytes.toBytes("rowkey"))` — create Put with row key
6. `put.addColumn(familyBytes, qualifierBytes, valueBytes)` — add columns
7. `table.put(put)` — execute the insert
8. `table.close()` then `conn.close()` — release resources

**Q14: What does ZooKeeper do in HBase?**

- Stores location of hbase:meta table (catalog of all regions)
- Monitors RegionServer health — detects crashes via ephemeral node expiry
- Notifies HMaster of RegionServer failures
- Clients contact ZooKeeper FIRST to find which RegionServer holds their data
- Provides distributed locking and HMaster leader election

**Q15: What is the difference between delete and deleteall?**

- `delete 'table','rowkey','cf:col'` — deletes one specific cell
- `deleteall 'table','rowkey'` — deletes all cells in the entire row

**Q16: Why must a table be disabled before ALTER?**

- ALTER changes the table schema (column family properties)
- RegionServers must stop serving the region to safely apply schema changes
- disable → stops all read/write on the table → ALTER safe to apply → enable resumes

**Q17: What are the default namespaces in HBase?**

- `default` — where user-created tables go if no namespace specified
- `hbase` — system tables: hbase:meta, hbase:namespace

**Q18: What is Region in HBase?**

- Basic unit of scalability and load distribution
- A contiguous sorted range of rows (by row key) within a table
- One Region → served by exactly one RegionServer
- As region grows too large → splits into two child regions
- HMaster assigns regions to RegionServers and rebalances load
