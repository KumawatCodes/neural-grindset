### Directory Commands

```bash
# Create a directory
hdfs dfs -mkdir /user/data
# Purpose: creates a new directory in HDFS

# Create directory with all parent directories
hdfs dfs -mkdir -p /user/himanshu/projects/hadoop
# Purpose: -p creates intermediate dirs if they don't exist (like mkdir -p in Linux)

# List directory contents
hdfs dfs -ls /
hdfs dfs -ls /user/
# Purpose: shows files and subdirectories with permissions, owner, size, date

# List recursively (all subdirectories too)
hdfs dfs -ls -R /user/
# Purpose: shows full directory tree

# Check if a path exists
hdfs dfs -test -e /user/data
echo $?
# Purpose: returns 0 if path exists, 1 if not
# -e = exists, -d = is directory, -f = is file, -z = is empty file

# Check file/directory existence explicitly
hdfs dfs -test -d /user/data && echo "EXISTS" || echo "NOT FOUND"

# Delete a directory (recursive — deletes all contents)
hdfs dfs -rm -r /user/data
# Purpose: -r flag needed to delete non-empty directory
# WARNING: no recycle bin — permanent delete

# Delete empty directory only
hdfs dfs -rmdir /user/emptydir
# Purpose: fails if directory has content (safety check)
```

### File Commands

```bash
# Create an empty file in HDFS
hdfs dfs -touchz /user/data/empty.txt
# Purpose: creates a zero-byte file — used to mark directories or test paths

# Check file emptiness
hdfs dfs -test -z /user/data/empty.txt
echo $?
# Purpose: returns 0 if file is empty (zero bytes), 1 if not

# Display file content
hdfs dfs -cat /user/data/file.txt
# Purpose: prints entire file content to terminal

# Display first N lines of file (head)
hdfs dfs -cat /user/data/file.txt | head -20
# Purpose: view beginning of large file without downloading it

# Display last N lines of file (tail)
hdfs dfs -tail /user/data/file.txt
# Purpose: shows last 1KB of file by default
# Note: hdfs dfs -tail only shows last 1KB — use cat | tail for specific lines

hdfs dfs -cat /user/data/file.txt | tail -10
# Shows last 10 lines

# Append content to existing HDFS file
hdfs dfs -appendToFile /tmp/extra.txt /user/data/file.txt
# Purpose: appends local file content to existing HDFS file
# Note: append only works if dfs.support.append=true in config

# Change file/directory permissions (chmod)
hdfs dfs -chmod 755 /user/data/file.txt
# Purpose: change permissions — same octal notation as Linux chmod
# 755 = rwxr-xr-x, 644 = rw-r--r--, 777 = rwxrwxrwx

# Change permissions recursively
hdfs dfs -chmod -R 755 /user/data/
# Purpose: apply permission change to all files in directory tree

# Change owner
hdfs dfs -chown hdfs:hadoop /user/data/file.txt
# Purpose: change file owner and group

# Show file metadata (block info, replication, permissions)
hdfs dfs -stat /user/data/file.txt
# Purpose: shows basic file stats — size, modification time
# Format options: %b=size, %n=name, %r=replication, %y=date

# Show detailed file metadata including block locations
hdfs fsck /user/data/file.txt -files -blocks -locations
# Purpose: MOST USEFUL for metadata — shows block IDs, DataNode locations,
#          replication count, file health status
# This is what teacher means by "find metadata"
```

### Copy Commands

```bash
# Copy from local filesystem to HDFS (put)
hdfs dfs -put /tmp/localfile.txt /user/data/
# Purpose: upload file from container local disk to HDFS
# -put and -copyFromLocal are identical

hdfs dfs -copyFromLocal /tmp/localfile.txt /user/data/
# Purpose: same as -put — explicit name for clarity

# Copy from HDFS to local filesystem (get)
hdfs dfs -get /user/data/file.txt /tmp/downloaded.txt
# Purpose: download file from HDFS to local disk
# -get and -copyToLocal are identical

hdfs dfs -copyToLocal /user/data/file.txt /tmp/downloaded.txt
# Purpose: same as -get

# Copy file within HDFS
hdfs dfs -cp /user/data/file.txt /user/backup/file.txt
# Purpose: copy file from one HDFS location to another
# Both source and destination are in HDFS

# Move file within HDFS
hdfs dfs -mv /user/data/file.txt /user/archive/file.txt
# Purpose: move (rename/relocate) file within HDFS
# Source path no longer exists after move

# Move one directory to another directory
hdfs dfs -mv /user/data/2023/ /user/archive/2023/
# Purpose: moves entire directory to new location within HDFS
```

---

### Merge Command

```bash
# Get merge — combine multiple HDFS files into one local file
hdfs dfs -getmerge /user/data/ /tmp/merged_output.txt
# Purpose: downloads all files in an HDFS directory and merges them into
#          one single local file in order of filename
# Very useful after MapReduce: merge part-r-00000, part-r-00001 etc into one file

# Getmerge with newline separator between files
hdfs dfs -getmerge -nl /user/data/ /tmp/merged_output.txt
# -nl adds a newline between each merged file

# Practical use — merge MapReduce output
hdfs dfs -getmerge /user/output/ /tmp/final_result.txt
cat /tmp/final_result.txt
```

---

### Checksum Command

```bash
# Get checksum of a file
hdfs dfs -checksum /user/data/file.txt
# Purpose: returns MD5/CRC32 checksum of file
# Use case: verify file integrity after copy — compare checksums
# If checksum matches = file transferred without corruption

# Example output:
# /user/data/file.txt    MD5-of-0MD5-of-512CRC32C    000002000000000...
```

---

### Count and Stats

```bash
# Count files and directories under a path
hdfs dfs -count /user/data/
# Purpose: shows directory count, file count, total size in bytes
# Output format: DIR_COUNT  FILE_COUNT  CONTENT_SIZE  PATH

# Show disk usage of files
hdfs dfs -du /user/data/
# Purpose: shows size of each file/subdirectory (in bytes)

# Show disk usage in human-readable format
hdfs dfs -du -h /user/data/
# -h: shows KB/MB/GB instead of raw bytes

# Show total disk usage of directory
hdfs dfs -du -s /user/data/
# -s: shows summary (single total) instead of per-file breakdown
```

---

### Admin Commands

```bash
# Show HDFS filesystem info (capacity, used, available)
hdfs dfsadmin -report
# Purpose: full cluster health report — DataNode status, block counts,
#          total capacity, used space, available space

# Show NameNode metadata info
hdfs dfsadmin -metasave /tmp/meta.txt
# Purpose: dumps NameNode metadata to a file — block mapping info

# Safe mode check (NameNode enters safe mode on startup)
hdfs dfsadmin -safemode get
# Purpose: check if NameNode is in safe mode
# In safe mode: reads allowed, writes not allowed
# Exits safe mode automatically after startup checks complete

hdfs dfsadmin -safemode leave
# Purpose: force exit safe mode (if stuck)
```

## SECTION 10 — Viva Questions and Answers

**Q1: What is HDFS?**

- Hadoop Distributed File System
- Stores large files as blocks distributed across multiple DataNodes
- NameNode manages metadata, DataNodes store actual data
- Designed for write-once, read-many workloads
- Default block size: 128MB, default replication: 3

**Q2: What is the purpose of NameNode?**

- Master node — manages filesystem metadata only (no data)
- Stores: file names, directory structure, block IDs, DataNode locations, permissions
- In-memory: namespace tree loaded into RAM for fast access
- Persists metadata via: FSImage (snapshot) + EditLog (change log)
- Single point of failure in Hadoop v1

**Q3: What is the purpose of Secondary NameNode?**

- NOT a backup — most common misconception
- Periodically merges FSImage + EditLog → creates new smaller FSImage
- Reduces NameNode restart time (smaller EditLog to replay)
- Runs checkpointing every 1 hour or when EditLog reaches 64MB

**Q4: What is the difference between -put and -copyFromLocal?**

- Functionally identical — both copy from local disk to HDFS
- -put: shorter, commonly used
- -copyFromLocal: more explicit, self-documenting name
- Same underlying implementation

**Q5: What is getmerge used for?**

- Downloads all files in an HDFS directory and merges into one local file
- Essential for MapReduce output — jobs produce multiple part files (part-r-00000, part-r-00001)
- getmerge combines all parts into one readable file

**Q6: What does hdfs fsck do?**

- Filesystem Check — shows detailed metadata for a file
- Displays: block IDs, block size, replication count, DataNode locations
- Checks file health: under-replicated blocks, corrupt blocks
- Most complete way to view file metadata in HDFS

**Q7: What is the purpose of -test flag?**

- Tests conditions without displaying output — returns exit code
- -e: path exists (0=yes, 1=no)
- -d: path is a directory
- -f: path is a file
- -z: file is empty (zero bytes)
- Used in scripts to check before performing operations

**Q8: What does checksum command do?**

- Returns CRC32/MD5 checksum of an HDFS file
- Used to verify file integrity after transfer
- Compare checksum before and after copy — identical = no corruption

**Q9: What is appendToFile?**

- Appends content of a local file to an existing HDFS file
- Requires dfs.support.append=true in Hadoop config
- HDFS files are generally immutable after write — append is the only modification allowed

**Q10: What is safe mode in HDFS?**

- Special read-only state of NameNode during startup
- In safe mode: can read files, cannot write or delete
- NameNode waits for DataNodes to report their blocks
- Exits safe mode automatically after sufficient blocks are reported
- Force exit: `hdfs dfsadmin -safemode leave`

**Q11: What is the difference between -rm and -rmdir?**

- -rm: deletes files, -rm -r deletes directories with all contents
- -rmdir: deletes ONLY empty directories — fails if directory has any content
- -rmdir is a safety net — prevents accidental deletion of non-empty directories

**Q12: What is replication in HDFS? Why 3?**

- Each block stored on 3 DataNodes by default (replication factor = 3)
- Rack-aware placement: 1st copy local node, 2nd different rack, 3rd same rack as 2nd
- Why 3: fault tolerance for node failure + rack failure, while keeping storage cost reasonable
- If one DataNode dies → NameNode detects (missed heartbeat) → triggers re-replication on another node

**Q13: What is block size in HDFS? Why so large?**

- Default: 128MB per block (older: 64MB)
- Large block size reduces: number of metadata entries in NameNode, number of seek operations
- Optimizes sequential read throughput
- Tradeoff: small files waste space (a 1KB file still uses a 128MB block)

**Q14: Explain HDFS write path**

1. Client requests write → NameNode picks 3 DataNodes (rack-aware)
2. Client writes to first DataNode
3. First DataNode replicates to second → second to third (pipeline replication)
4. Acknowledgment flows back: 3rd → 2nd → 1st → client
5. Client sends next block, repeats
6. After all blocks → client closes → NameNode marks file complete

**Q15: Explain HDFS read path**

1. Client requests file → NameNode returns block list with DataNode locations
2. Client reads each block from the NEAREST DataNode (network topology aware)
3. If DataNode fails during read → client automatically switches to another replica
4. No data passes through NameNode — direct client-DataNode transfer

**Q16: What is a heartbeat in HDFS?**

- DataNodes send heartbeat to NameNode every 3 seconds
- Signals: "I am alive and healthy"
- If NameNode receives no heartbeat for 10 minutes → marks DataNode as dead
- Triggers re-replication of blocks that were on dead DataNode

**Q17: What is a block report?**

- DataNodes send complete list of all blocks they hold to NameNode every 6 hours
- NameNode uses this to verify replication counts and detect corrupt/missing blocks
- Different from heartbeat: heartbeat = liveness, block report = data inventory
